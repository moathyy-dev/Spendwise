# معمارية SpendWise

## نظرة عامة

SpendWise مبني كطبقات واضحة الفصل، بحيث يمكن استبدال أو توسيع أي طبقة دون التأثير على الأخرى:

```
واجهة المستخدم (Streamlit)
        │
        ▼
   محرّك الاستيراد (import_service)
        │
   ┌────┼────┬────────┬───────────┬───────────┐
   ▼    ▼    ▼         ▼           ▼           ▼
قراءة  تطابق  تنقية    تصنيف       كشف          تحويل
ملفات  أعمدة  خصوصية   (محلي+AI)  (تكرار/تحويل  عملات
                                   /استرداد)
        │
        ▼
   قاعدة البيانات (SQLAlchemy + SQLite)
        │
        ▼
   التحليلات (analytics) ──▶ التصدير (export)
```

## المبادئ التصميمية

1. **لا كتابة جزئية**: أي ملف مستورد يُعالج بالكامل في الذاكرة (`StagedRow`) ولا يُكتب أي شيء لقاعدة البيانات إلا بعد موافقة صريحة من المستخدم عبر `commit_import`.
2. **الخصوصية بالتصميم**: كل ما يتجاوز حدود التنقية (`sanitize/`) لا يصل لأي طبقة تالية — لا لقاعدة البيانات ولا لمزوّد الذكاء الاصطناعي.
3. **مزوّدون قابلون للاستبدال**: `ai_provider/` و`fx_provider/` كلاهما واجهات مجردة (Abstract Base Class) بحيث يمكن إضافة مزوّد جديد (مثل Ollama محليًا) بإنشاء ملف جديد ينفّذ نفس الواجهة، دون تعديل بقية التطبيق.
4. **الأموال بدقة عشرية**: جميع الحسابات المالية تستخدم `Decimal` (`money.py`) — لا استخدام لأعداد الفاصلة العائمة الثنائية أبدًا لتفادي أخطاء التقريب.
5. **الترحيلات هي مصدر الحقيقة**: أي تغيير في هيكل قاعدة البيانات يمر عبر Alembic — لا تعديل يدوي مباشر على قاعدة البيانات.

## الطبقات بالتفصيل

| الطبقة | المسؤولية |
|---|---|
| `ingestion/` | قراءة ملفات Excel وPDF واستخراج جداول خام |
| `mapping/` | تخمين تطابق الأعمدة (تاريخ/مبلغ/بيان...) وتطبيعها لشكل موحّد |
| `sanitize/` | إزالة أي معلومات حساسة من النص، وحساب البصمات أحادية الاتجاه |
| `categorize/` | تصنيف المعاملات عبر قواعد محلية طبقية ثم الذكاء الاصطناعي كخيار احتياطي |
| `ai_provider/` | واجهة موحّدة لأي مزوّد ذكاء اصطناعي |
| `fx_provider/` | واجهة موحّدة لأسعار الصرف (يدوي أو عبر الإنترنت) |
| `detect/` | كشف التكرار، التحويلات بين الحسابات، الاسترداد، الاشتراكات المتكررة، الشذوذ الإحصائي |
| `import_service.py` | تنسيق تدفق الاستيراد الكامل على بيانات مؤقتة في الذاكرة |
| `db/` | نماذج قاعدة البيانات (SQLAlchemy) والترحيلات (Alembic) |
| `analytics/` | حساب المقاييس الشهرية، المقارنات، حالة الميزانية، التوصيات |
| `export/` | تصدير PDF/Excel، النسخ الاحتياطي، الحزم المحمولة |
| `ui/` | صفحات Streamlit |

## نقاط التوسع الموثّقة

- **تصنيفات فرعية للميزانية**: نموذج `Budget` مرتبط حاليًا بـ (عضو، شهر) فقط؛ يمكن إضافة عمود `category_id` اختياري مستقبلًا دون كسر التوافق.
- **مزوّدو ذكاء اصطناعي إضافيون**: أضف ملفًا جديدًا في `ai_provider/` ينفّذ `AIProvider`، وسجّله في `ai_provider/__init__.py::build_ai_provider`.
- **مزوّدو أسعار صرف إضافيون**: نفس النمط في `fx_provider/`.
- **تصنيفات/قواعد متقدمة**: نموذج `Rule` يدعم بالفعل أنواعًا متعددة (`exact`, `merchant_normalized`, `keyword`, `learned`) وأولوية رقمية، فيمكن إضافة أنواع جديدة (مثل التعبيرات النمطية Regex) بإضافة قيمة جديدة لـ `RuleType` ومنطق مطابقة مقابل في `rules_engine.py`.
- **حسابات متعددة العملات المتقدمة**: نموذج `FxRate` يحتفظ بالمصدر والتاريخ، ما يسمح مستقبلًا بعرض تاريخ أسعار الصرف المستخدمة.
